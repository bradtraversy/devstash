# Link Previews and Save to Stash

## Overview

Two things make a shared DevStash link behave like a real gist link. First, every shared item and collection gets a generated Open Graph image, so a link pasted into Slack, X, Discord, or iMessage unfurls as a card showing the title, the handle, and the first lines of the code in the app's own font and colors, instead of the site-wide DevStash card. Second, every public page gets a `Save to your stash` button: a signed-in viewer copies the item, or the whole collection with its items in order, into their own account as private copies; a signed-out viewer is sent through sign-in and the save finishes when they land back on the page.

No migration, no new environment variable, no new dependency. Two font files are vendored into the repo under the Open Font License. The free tier keeps its limits: a save counts like any other create, and a collection save that would push a free account past 50 items or 3 collections is refused with the usual upgrade message.

Branch: `feature/link-previews-and-save` off `main`, one implementation commit, then a pull request.

## Requirements

### Open Graph images

- Two route handlers render the images, as siblings of the existing `raw` routes:
  - `src/app/s/[shortId]/og/route.tsx` for a shared item.
  - `src/app/[handle]/[slug]/og/route.tsx` for a shared collection.
- Both export `dynamic = 'force-static'` and `generateStaticParams` returning `[]`, so each image renders on its first request and stays in the full route cache next to its page until an owner write revalidates it. Neither reads search params, cookies, or headers. A route test asserts both exports.
- Both validate and lowercase their segments the way their pages do (`SHORT_ID_PATTERN`, `normalizePublicSegment`). A malformed segment, a case variant, an unknown or private target, or a handleless owner is `notFound()` with no image rendered; the case variant is not redirected because nothing links to it.
- The item route resolves through `getPublicItem(shortId)` only. A short id that belongs to a collection has no item image; the collection page carries its own. The collection route resolves through `getPublicCollection(handle, slug)`; a retired slug is `notFound()` (the page redirects it, the image is only ever requested at the live URL from the page's metadata).
- Response: `image/png`, 1200 by 630, built with `ImageResponse` from `next/og`, with `Cache-Control: public, max-age=0, must-revalidate` set explicitly because the renderer's own default is a year of immutable caching and these images change with their pages. The renderer takes inline styles only, and `src/lib/og/` is the one place they are allowed, as `src/app/opengraph-image.tsx` already notes.
- `src/lib/og/fonts.ts` loads `Geist-SemiBold.ttf` and `GeistMono-Regular.ttf` from `src/lib/og/fonts/` with `readFile(join(process.cwd(), ...))`, the form the Next.js metadata docs use so output file tracing bundles them, and caches the buffers in module scope. Both files come from the `geist` npm package (version 1.7.2, Vercel, SIL Open Font License 1.1) and the package's `LICENSE.txt` is copied next to them as `OFL.txt`. `ImageResponse` replaces its default font when `fonts` is given, so the sans face must be vendored too; the image uses `Geist` weight 600 for the title and `Geist Mono` weight 400 for everything else.
- `src/lib/og/lines.ts` (pure):
  - `previewLines(content, maxLines)`: splits on `\n`, drops a trailing empty line, expands tabs to two spaces, strips `\r`, cuts each line at 120 characters, and returns at most `maxLines` lines plus a `truncated` flag.
  - `OG_PREVIEW_LINES = 10` for items and `OG_COLLECTION_ROWS = 8` for collections.
- `src/lib/public/highlight.ts` gains `highlightLines(code, languageId)`: the same lazily created highlighter and grammar loading as `highlightCode`, returning `{ content, color }[][]` from `codeToTokensBase` with the `dark-plus` theme, `color` defaulting to `#d4d4d4`. Callers pass only the preview lines, never the whole content.
- `src/lib/og/cards.tsx` (pure JSX, no data access):
  - `ItemCard({ item, lines, truncated })`: a 1200 by 630 dark panel (the gradient from the site-wide image), 48px padding. Top row: a 16px dot in the item type color, the title in Geist SemiBold 44px on one line with ellipsis, and the kind label on the right in mono 22px muted (`languageLabel` for snippets, `Terminal` for commands, the capitalised type otherwise). Middle: a rounded code panel (`#18181b` on a `#27272a` border, 24px padding) holding the token lines in mono 22px with a 33px line height, `whiteSpace: 'pre'`, horizontal overflow hidden, and a bottom fade overlay when `truncated`. Footer: `@{handle}` left and `devstash.io` right, mono 22px muted. The panel body by type: snippets and commands show highlighted lines (commands through the bash grammar); notes and prompts show their lines through the markdown grammar; a link shows its URL in emerald; an image or file shows its file name and size; empty content shows `(empty)` muted.
  - `CollectionCard({ collection })`: the same frame with the collection name as the title and `{n} items` as the right label. The panel lists up to `OG_COLLECTION_ROWS` items in position order, each a row with the type dot, the item title in mono 22px, and the kind label right-aligned muted; when more items remain the last row reads `+ {n} more` muted. An empty collection shows `No items yet`.
  - Every element with more than one child declares `display: 'flex'`, as the renderer requires.
- `src/lib/og/render.tsx`: `renderOgImage(element)` returns `new ImageResponse(element, { width: 1200, height: 630, fonts })` with the cached fonts; the two routes call only this.
- `src/lib/public/paths.ts` gains `publicShortOgPath(shortId)` (`/s/{shortId}/og`), `publicCollectionOgPath(handle, slug)` (`/{handle}/{slug}/og`), and `versionedPath(path, date)` (`{path}?v={date.getTime()}`).
- `src/lib/public/metadata.ts`: `publicItemMetadata` and `publicCollectionMetadata` set `openGraph.images` to one entry `{ url, width: 1200, height: 630, alt: title }` and `twitter.images` to `[url]`, where `url` is the versioned og path built from the item's `updatedAt`, or for a collection from `contentUpdatedAt`, a new `PublicCollection` field holding the latest of the collection row's and its listed items' `updatedAt` (an item rename changes the card without touching the collection row). The route cache ignores the query; the version only makes social platforms, which cache images by URL for days, fetch a fresh image after an edit changes the page metadata.
- Revalidation: the og path joins every lookup that returns its page. `toPaths` in `src/lib/db/public.ts` adds `publicCollectionOgPath(handle, slug)` for the live slug (not for retired slugs); `publicPathsForItem` and `publicPathsForUser` add `publicShortOgPath` for every shared item they return. Nothing changes in the actions: they already revalidate the union before and after each write.

### Save to your stash

- `src/lib/db/save.ts` (writes; every read inside carries the shared filter):
  - `copySharedItem(userId, shortId, canCreate)`: reads the source item with the public page's filter (`visibility: { not: 'PRIVATE' }` and an owner with a handle), its type name, and its tag names. Returns `{ status: 'not-found' }` when missing or private, `{ status: 'own' }` when `source.userId === userId`, `{ status: 'unsupported' }` for `file` and `image` types, `{ status: 'limit' }` when the caller's cap check (`canCreate`) is false, in that order so a dead link or the owner's own item never gets the upgrade message, otherwise creates the copy through the existing `createItem` (type, title, description, content, url, language, tags, no collections, private) and returns `{ status: 'saved', itemId, typeName }`. The copy gets a fresh short id, `isFavorite` and `isPinned` false, and no `publishedAt`.
  - `copySharedCollection(userId, handle, slug)`: reads the source collection with the shared filter and the owner's handle, and all of its join rows in `COLLECTION_ITEM_ORDER` with each item's type and tag names (no page limit; the cap below bounds it for free accounts). Returns `not-found`, `own`, or `{ status: 'empty' }` when no item is a text or link type, otherwise runs one transaction that creates the collection (same name and description, slug from `collectionSlugBase` deduped against the user's slugs, a short id, and the retired-slug history cleanup, through an `insertCollectionTx(tx, userId, data)` extracted from `insertCollection` so both paths share it), then creates one item per copyable source item with `freeShortId(tx)` (exported from `items.ts`), the same fields as above, and a join row at `position` equal to its index among the copied items. The whole transaction is wrapped in the one-retry-on-unique-violation pattern `createCollection` uses. Returns `{ status: 'saved', collectionId, copied, skipped }` where `skipped` counts the file and image items left out.
  - `countCopyableItems` is a pure helper over type names used by both the cap check and the copy, exported for tests: copyable types are `snippet`, `command`, `note`, `prompt`, `link`.
- `src/actions/save.ts` (`'use server'`):
  - `saveSharedItem({ shortId })`: `getAuthedSession`, Zod (`SHORT_ID_PATTERN` after lowercasing), then inside one `try`: `getUserUsage` and `copySharedItem(userId, shortId, usage.canCreateItem)`. Maps `not-found` to `This item is no longer shared`, `own` to `This is already in your stash`, `unsupported` to `Files cannot be saved yet`, `limit` to the existing 50-item message. Success data: `{ itemId, typeName }`.
  - `saveSharedCollection({ handle, slug })`: `getAuthedSession`, Zod (`normalizePublicSegment` on both), then inside one `try`: `describeSharedCollection(handle, slug)` from `save.ts` returning `{ ownerId, copyable }` or null; null is `This collection is no longer shared`, the caller's own collection is `This is already in your stash`, zero copyable items is `This collection has nothing that can be saved yet`, and more than `SAVE_COLLECTION_ITEM_LIMIT` (200) is `Collections with more than 200 items cannot be saved yet` for every account, since the copy is one transaction. Only then `getUserUsage`: the existing 3-collection message when the collection cap is reached, and `Saving this collection needs {n} item slots and your free plan has {m} left. Upgrade to Pro for unlimited items.` when `itemCount + n > MAX_ITEMS` for a free user. Then `copySharedCollection`, mapping the same statuses for the case where the source changed under the save. Success data: `{ collectionId, copied, skipped }`.
  - The limit messages and `MAX_ITEMS`, `MAX_COLLECTIONS`, and `SAVE_COLLECTION_ITEM_LIMIT` live in `src/lib/constants/limits.ts`; `usage.ts` re-exports the two maximums and the item and collection create actions use the shared messages instead of their own copies.
  - Copies are private, so no public path changes and no revalidation; both actions return `ActionResult`.
- `src/lib/constants/action-errors.ts` exports `UNAUTHORIZED_ERROR = 'Unauthorized'` and `getAuthedSession` uses it, so the client can tell a signed-out result from a failure without a second string and without importing the auth module. The copyable type list (`COPYABLE_ITEM_TYPES`, `isCopyableType`) lives in `src/lib/constants/item-types.ts` for the same reason: the public item view decides whether to render the button with it.
- `src/components/public/save-button.tsx` (client): props `{ target: { kind: 'item'; shortId } | { kind: 'collection'; handle; slug }, compact?: boolean }`. Renders an outline `Button` with the `BookmarkPlus` icon and the label `Save to your stash` (`Save` with the full label as `title` when `compact`). On click it runs the matching action inside `useTransition`:
  - `UNAUTHORIZED_ERROR`: `router.push('/sign-in?callbackUrl=' + encodeURIComponent(pathname + '?save=1'))`.
  - Success: `toast.success` with `Saved to your stash` for an item (`Saved {copied} items to your stash`, plus `, {skipped} files skipped` when any, for a collection) and an `Open` action that pushes `/items/{typeName}s` or `/collections/{collectionId}`.
  - Error: `toast.error(result.error)`.
  - On mount, a `useEffect` reads `window.location.search`; when it holds `save=1` it replaces the URL without the query through `history.replaceState` and runs the same save once, so a viewer who signed in to save lands back on the page and sees the toast. A resumed save that finds no session returns quietly instead of bouncing to sign-in again, so a viewer who abandoned sign-in and came back, or who received a copied `?save=1` link, just sees the page. Reading `window.location` instead of `useSearchParams` keeps the page statically rendered without a Suspense boundary.
  - The page reads no session, so the button renders for every viewer including the owner; the owner's click gets the `own` message.
- `PublicItemView`: the button sits at the right end of the meta line (`@handle · kind · Updated`), which becomes a flex row that wraps on small screens. It is omitted for `file` and `image` items, which have nothing to copy until public file access exists.
- `CollectionHeader`: a compact `SaveButton` joins the action group before `Copy as markdown`.
- `src/actions/auth.ts`: `signInWithGitHub` accepts an optional `redirectTo` through form data, run through `safeRedirectPath`, so a GitHub sign-in started from the save flow also returns to the page. `GitHubAuthSection` gains an optional `callbackUrl` prop rendered as a hidden input; `SignInForm` passes the one it already parses. The register form is unchanged; a brand-new viewer registers, verifies, signs in, and lands on the dashboard. Carrying the return path through registration and email verification belongs to the homepage paste-to-share feature, which needs the same thing.

## Notes

- The og routes are `force-static` rather than `ImageResponse` through the `opengraph-image.tsx` file convention because the convention appends a build hash to the image URL, which `revalidatePath` cannot target, and the path must join the same revalidation lists as the page so a page that goes private takes its image with it.
- The `?v=` version lives only in the metadata URL. The route cache keys on the path, so one cached image serves every version, and the owner write that changes `updatedAt` also revalidates the image path.
- Vendoring two TTF files (about 275 KB) is the smallest reliable way to get the app's fonts into the renderer: `next/font` emits woff2, which the renderer cannot read, and reading from `node_modules` at runtime is not traced into the deployed function.
- The save actions use `createItem` and the collection insert helpers so short ids, tags, positions, slug history cleanup, and the unique-violation retry stay in one place.
- The save button renders for everyone because the public pages are cached without a session; an `own` click costs one request and a clear message, and keeps the pages fully static.
